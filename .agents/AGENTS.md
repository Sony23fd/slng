# Төслийн хөгжүүлэлтийн болон тооцооллын хатуу дүрмүүд (AGENTS.md)

Энэхүү файл нь Selenge хэвлэлийн үйлдвэрийн захиалга болон үнийн тооцооллын системийн амин сүнс болсон архитектур, тооцооллын логик болон код бичих стандартуудыг тодорхойлно. Энэ төсөл дээр ажиллах аливаа AI агент болон хөгжүүлэгч эдгээр дүрмийг **ЯГ ТАГ** мөрдөх үүрэгтэй.

---

## 🔴 1. ХАТУУ ХОРИГЛОХ ДҮРЭМ (CRITICAL CALCULATION SAFEGUARDS)

1. **Тооцооллын логикт дураараа хүрэхийг ХАТУУ ХОРИГЛОНО**:
   - Захиалгын маягтын (`OrderForm.tsx`) цаас тооцох (`calculatePaperDivision`, `calculateSetups`), бүрэлт тооцох (`calculateCoatingOperation`), ажиллагааны томьёо бодох (`evaluateOperationFormula`), хатуу хавтас болон супер хавтасны туслах бодолтууд (`getHardcoverAuxiliarySpecs`, `getSuperCoverSpecs`), болон `useEffect` доторх бодолтуудыг UI шинэчлэх, загвар (style) засах эсвэл код цэгцлэх (refactor) нэрийдлээр өөрчлөх, устгах, хөндөхийг ХАТУУ ХОРИГЛОНО.
   - Энэ дүрмийг зөрчиж бодолтын логик, хуваалт эсвэл үнийн томьёог эвдсэн аливаа кодын өөрчлөлт нь ноцтой гэмтэлд (system regression) тооцогдоно.
2. **Ажиллагааны өртөг ба Үнийн саналд оролцох стандарт (DEFAULT ZERO-COST OPERATIONS)**:
   - Бүх төрлийн туслах болон үндсэн ажиллагаанууд (`Хатуу хавтас`, `Хөөсөн хатуу хавтас`, `Супер хавтас`, `Блокон оёо`, `Лак`, `Клише`, `Огтлоо`, `Наалт`, `Үдээ` гэх мэт)-ыг захиалга болон загварт нэмэхэд **анхдагчаар `unit_cost: 0` (0 ₮)** орно.
   - Эдгээр нь үндсэн үнийн саналд нэмэлт зардал үүсгэхгүй ба үйлдвэрийн цехийн дамжлагын технологийн зааварчилгаа болон Ажлын хуудас (Job Ticket)-д бүрэн хэвлэгдэнэ.
   - Хэрэв тухайн захиалга дээр тодорхой ажиллагааны өртгийг үнийн саналд оруулах шаардлагатай бол захиалгын маягтын `Нэгж өртөг` баганад үнийг гараар бичнэ. Гараар үнэ бичсэн тохиолдолд $\text{Нийт өртөг} = \text{Тоо} \times \text{Нэгж өртөг}$ бодогдож, үнийн саналд бодитоор тусгагдана.
3. **Тооцоололд өөрчлөлт оруулах журам**:
   - Хэрэв тооцооллын томьёо эсвэл логикт өөрчлөлт оруулах шаардлага гарвал **ЗААВАЛ** хэрэглэгчээс (USER) урьдчилан тодорхой зөвшөөрөл авч, хэвлэлийн үйлдвэрлэлийн физик бодолтоор (цаасны хуваалт, талбай гэх мэт) баталгаажуулсны дараа л хэрэгжүүлнэ.

## 💡 2. ТУСГАЙЛСАН БОДОЛТУУДЫН СТАНДАРТ (ESTABLISHED CALCULATIONS)

Аливаа тооцооллын алдааг засварлах эсвэл шалгахдаа дараах батлагдсан бизнесийн дүрмүүдийг үндэслэл болгоно:

### А. Брошур (Brochure)
- **[M4] Хэвлэлийн хуудас**: Үргэлж **`1`** гэж албадан тохируулагдана.
- **[M5] Үндсэн хэвлэх тоо**: Захиалгын нийт тоог цаасны хуваалтад хувааж гаргана. E.g., $\text{M5} = \lceil \text{Захиалгын нийт тоо} / \text{calculatePaperDivision(Хэв. хэмжээ, Бүтээгдэхүүний хэмжээ)} \rceil$.

### Б. Цаасан тор (Paper Bag)
- **Дэлгээс хэмжээ (Flat sheet size)**: Тор нь 3 хэмжээст биет тул хавтгай дэлгээсийг дараах томьёогоор бодно:
  - $\text{Дэлгээс Өргөн} = (\text{Өргөн} + \text{Хажуу}) \times 2$
  - $\text{Дэлгээс Өндөр} = \text{Өндөр} + \text{Амсар нугалаа} + \text{Ёроол нугалаа}$ *(Амсар болон Ёроол стандарт нь тус бүр 6см)*
- **Хэмжээ хадгалах ба сэргээх (Persistence & Presets)**:
  - Торны хэмжээ (Өндөр, Өргөн, Хажуу, Амсар, Ёроол) нь захиалгын `size` (`Тор WхHхG (Дэлгээс: FWхFHсм)`) болон `sub_size` (`WхHхGсм (Амсар: TFсм, Ёроол: BFсм)`) талбарт хадгалагдаж, захиалга засахад (`initialData`) болон загвар ачаалахад автоматаар сэргээгдэнэ.
  - Тогтмол ашиглагддаг торны хэмжээг `BAG_SIZE` төрлөөр constants санд хадгалж, бэлэн бэлдэцийн сонголтоос шууд сонгох болон шинээр хадгалах боломжтой.
- **Цаасны тооцоо ба Хэвлэлийн хуудас (Press Sheet)**:
  - Дэлгээс хэмжээ нь B2 (720х520мм) эсвэл А2 материалд багтана.
  - Торон дээр хэвлэлийн хуудсыг (`press_sheet`) гараар чөлөөтэй бичих боломжтой (стандартаар 1, том торонд 2 хэсэг дэлгээс орвол 2, жижиг торонд 0.5 гэх мэт).
  - Нийт тооцоо: $\text{Total Qty} = (\text{Base} \times \text{PressSheet}) + (\text{Extra} \times \text{Setups})$.
  - B1 том цааснаас B2 зүсэх тул **[M8] Хуваалт = 2**, том цаасны хэрэгцээт тоо **[M9] = \lceil \text{Total Qty} / 2 \rceil** байна.
- **CTP хавтан**:
  - Торон дээр Komori B2 (74.5х60.5) CTP хавтан автомат бодогдоно (4+0 үед 4 хавтан, 4+4 үед 8 хавтан гэх мэт). Press sheet нь 2 бол 8 хавтан болж тохируулгаараа үржигдэнэ.

### В. Бүрэлт (Coating)
- **10 Төрлийн бүрэлтийн материалын задаргаа (10 Coating Materials Standard)**:
  - Бүрэлт нь дараах 10 тодорхой материал ба өргөний сонголттой байна:
    - **Хятад гялгар**:
      - `Бүрэлт гялгар Хятад 36 см` (өргөн: 36см / B3, A3, коэф: 0.004)
      - `Бүрэлт гялгар Хятад 44 см` (өргөн: 44см / A2, коэф: 0.006)
      - `Бүрэлт гялгар Хятад 54 см` (өргөн: 54см / B2, коэф: 0.007)
    - **Хятад матт**:
      - `Бүрэлт матт Хятад 36 см` (өргөн: 36см / B3, A3, коэф: 0.004)
      - `Бүрэлт матт Хятад 44 см` (өргөн: 44см / A2, коэф: 0.006)
      - `Бүрэлт матт Хятад 54 см` (өргөн: 54см / B2, коэф: 0.007)
    - **Солонгос / Тусгай өнгөлгөөтэй**:
      - `Бүрэлт Илгэн  Со 44` (өргөн: 44см / A2, коэф: 0.006)
      - `Бүрэлт гялгар/эмбосстой Со 36см` (өргөн: 36см / B3, A3, коэф: 0.004)
      - `Бүрэлт матт/эмбосстой Со 36см` (өргөн: 36см / B3, A3, коэф: 0.004)
      - `Бүрэлт матт/эмбосстой Со 44см` (өргөн: 44см / A2, коэф: 0.006)
  - **Үнийн стандарт**: Бүрэлтийн бүх 10 материалын суурь нэгж өртөг нь **1,500₮** байна.
  - **Ажиллагааны өртөг**: Бүрэлтийн ажиллагаа (үйлдэл) нь AGENTS.md дүрэм 1.2-ын дагуу анхдагчаар **0 ₮** байна. Хэрэглэгч нэгж өртөг гараар бичвэл үнийн саналд бодитоор тусгагдана.
- **Хавтастай синхрончлох стандарт (Cover Synchronization Rule)**:
  - Бүрэлт нь хавтас (эсвэл үндсэн хэвлэгдэх материал) дээр хийгддэг тул **Хэвлэлийн хуудас (`press_sheet`)** болон **Хуваалт (`divide_by`)** нь хавтасны үзүүлэлтийг яг тэр чигт нь өвлөн авч харуулна (`—` зураасаар хаахгүй).
  - Захиалгын маягтын хүснэгтэд ногоон тодотголтойгоор `{press_sheet} х.х` болон `{divide_by} хуваалт` гэж синхрончлогдон харагдана.
- **Хэмжээ (өргөн) сонголт**:
  - Хүснэгтийн "Хэмжээ" баганад тухайн бүрэлтийн боломжит өргөнүүд (`36 см`, `44 см`, `54 см`)-ийг сонгох боломжтой ба өргөнийг өөрчлөхөд материалын нэр автоматаар шинэчлэгдэж, метр тооцоолол (`total_qty * coef`) дахин бодогдоно.
- **Хавтасны бүрэлтийн хадаас ба томьёо**:
  - Хавтасны бүрэлтийн мөрөнд **"Хадаас"** (нэмэлт хуудас) оруулах тусгай input талбар байрлана.
  - Хэрэгцээт хуулга (метр) тооцоо: $\text{Sheet Qty} = (\text{M5 Үндсэн тоо} + \text{Хадаас}) \times \text{Коэффициент}$.
- **Хадаасны стандарт норм (`calculateCoatingMakeready`)**:
  - **Энгийн бүрэлт**: $\le 3,000$ үед **20 хадаас**, $> 3,000$ үед **50 хадаас**
  - **Эмбосс бүрэлт**: $\le 3,000$ үед **40 хадаас**, $> 3,000$ үед **50 хадаас**
  - **Лактай бүрэлт** (`Хэсэгчилсэн`, `Барзгар`, `Бүтэн`): Үргэлж **60 хадаас**
  - **Лак + Эмбосс зэрэг орсон үед**: Хамгийн өндөр технологийн нарийвчлал шаардах **60 хадаас**
- **Коэффициентийн хэмжээ хамаарал**:
  - `54 см` эсвэл `B2` хэмжээ $\rightarrow$ Коэффициент: **`0.007`**
  - `44 см` эсвэл `A2` хэмжээ $\rightarrow$ Коэффициент: **`0.006`**
  - `36 см` эсвэл `A3`/`B3`/`B4` хэмжээ $\rightarrow$ Коэффициент: **`0.004`**

### Г. Оосор (Bag Straps)
- 1 торонд 2 ш оосор орох тул Ажиллагааны томьёо нь үргэлж `total_qty * 2` байна.

### Д. Үйлдвэрлэлийн 7 үндсэн ажиллагааны автомат систем ба Томьёо (7 Automated Core Operations Standard)
1. **Үйлдвэрлэлийн 7 гол ажиллагаа**:
   - Захиалгын маягт болон бүх 26 бэлэн загварт үйлдвэрлэлийн дараах 7 ажиллагааны бичиглэл болон бодолт нь автоматаар үүсэж, бодит параметрээр бодогдоно:
     - **Хэвлэх (${colors} өнгө)**: Офсет төрлийн бүтээгдэхүүнд хавтасны болон дотор хуудасны өнгөөр автомат үүснэ. Тоо нь цаасны хэвлэх бодит тоо (`cover_base_sheets`, `inner_base_sheets`, `total_base_sheets`)-оор бодогдоно. Түргэн хэвлэл (Konica, EPSON, Шуурхай принт, Бал, Даралт, Промо)-д орохгүй.
     - **Шалгах**: Офсет бүтээгдэхүүнд автомат үүснэ. Тоо нь хэвлэгдэх бодит хуудасны тоо `total_base_sheets` (эсвэл `total_qty`)-оор бодогдоно.
     - **Цуглуулга**: `Холио` болон `Цуглуулга` нь ижил утгатай тул зөвхөн `Цуглуулга` нэршлийг үлдээнэ. Номын ангилал, хуудас > 4, Хортой маягт болон Сонинд `total_base_sheets`-ээр бодогдоно.
     - **Үдээ**: Үдэлтийн төрөл `Үдээстэй` байх үед `Үдээ (Унаа үдээ)` автомат нэмэгдэж, `total_qty` ширхэгээр бодогдоно (`Наалт` автоматаар хасагдана).
     - **Наалт**: Үдэлтийн төрөл `Наалттай`, `Хатуу хавтастай`, `Хөндлөн хатуу хавтастай` байх үед `Наалт` автомат нэмэгдэж, `total_qty` ширхэгээр бодогдоно (`Үдээ` автоматаар хасагдана).
     - **Огтлоо**: Ном, сэтгүүл, брошурт `Огтлоо (Гурван талт)` (тоо: 2); томоохон дэлгээс/постер/сонинд `Огтлоо (Том)` (тоо: 1); бусад энгийн хуудсанд `Огтлоо (Жижиг)` (тоо: 1) автоматаар үүснэ.
     - **Чанарын эцсийн хяналт**: Бүх 27 ангиллын захиалга, загварт заавал автоматаар орно. Тоо: `total_qty`, Үе шат: `PACKAGING`, Анхдагч өртөг: `0 ₮`.
2. **Хасагдсан ба цэвэрлэгдсэн хуучирсан ажиллагаанууд**:
   - `Холио` (Цуглуулга болсон), `Хөөсөн хатуу хавтас хийх` (Хатуу хавтастай нийлсэн), `Цаас амраах / Хэвэнд бэлтгэх`, `Өнгө тааруулах / Сигнатур тулгах`, `Хатаалт хүлээх`, `QR / Баркод уншиж шалгах`, `Тусгай боодол / Хайрцаглах` зэрэг ажиллагаануудыг систем болон баазаас бүрэн устгасан бөгөөд дахин системд үүсгэхгүй.
3. **Үнийн саналд оролцох дүрэм**:
   - Бүх автомат ажиллагаанууд анхдагчаар `unit_cost: 0` (0 ₮) байна. Хэрэглэгч гараар нэгж өртөг бичсэн тохиолдолд л үнийн саналд тооцогдоно.
4. **Ажиллагааны хэмжигдэхүүн (Operations Formulas)**:
   - Дараах ажиллагаануудын тооцоолол нь захиалгын нийт тоогоор биш, хэвлэгдэх цаасны бодит тоогоор (Үндсэн хэвлэх тоо $\times$ Хэвлэлийн хуудас) буюу систем дэх `total_base_sheets` хувьсагчаар бодогдоно:
     - **Нугалаа**, **Шалгах**, **Цуглуулга**
     - **Хэвлэгч (1 өнгө, 2 өнгө, 4 өнгө, 5 өнгө)**
   - Эдгээр томьёог `seed-prices.ts` дотор `expr: 'total_base_sheets'` гэж хатуу тохируулж өгсөн бөгөөд дураараа `total_qty` руу буцаахыг хориглоно.

### Ё. Машины хадаас ба Тохируулга (Makeready & Setups Standard)
- **Хадаасны шатлал (`calculateMakeready`)**:
  - $\text{Base} \le 1000 \rightarrow 100$ хуудас
  - $\text{Base} \le 2000 \rightarrow 150$ хуудас
  - $\text{Base} \le 4000 \rightarrow 200$ хуудас
  - $\text{Base} \le 5000 \rightarrow 300$ хуудас
  - $\text{Base} \le 10000 \rightarrow 400$ хуудас
  - $\text{Base} \le 15000 \rightarrow 500$ хуудас
  - $\text{Base} \le 20000 \rightarrow 600$ хуудас
  - $\text{Base} \le 25000 \rightarrow 800$ хуудас
  - $\text{Base} \le 30000 \rightarrow 900$ хуудас
  - $\text{Base} > 30000 \rightarrow 1000$ хуудас
- **Тохируулга тооцох (`calculateSetups`)**:
  - $\text{Бүхэл хуудас} = \lfloor \text{press\_sheet} \rfloor$
  - Бутархай хуудасны үед $\text{popcount}(\text{round}(\text{fraction} \times \text{divisions}))$ ашиглан нэмэлт тохируулгын тоог гаргана.
- **Нийт цаасны тооцоо**:
  - $\text{Total Qty} = (\text{Base} \times \text{PressSheet}) + (\text{Extra} \times \text{Setups})$
  - $\text{Sheet Qty (Том цаасны тоо)} = \lceil \text{Total Qty} / \text{DivideBy} \rceil$

### Ж. CTP Хавтан тооцох физик стандарт (CTP Plates Calculation)
- **Хамрах хүрээ (Universal Offset CTP)**:
  - CTP хавтан нь офсет технологиор хэвлэгдэх бүх төрлийн бүтээгдэхүүн (Ном, Сэтгүүл, Брошур, Цаасан тор, Хайрцаг гэх мэт)-д автоматаар бодогдоно.
  - Зөвхөн дижитал принтерээр хэвлэгдэх **"Түргэн хэвлэл"** ангилалд CTP хавтан тооцогдохгүй (хасагдана).
- **Тогтмол үнэ**:
  - `CTP_PLATE_PRICE = 8,800₮`: Том CTP хавтан 76*60.5 / 74.5*60.5 (Komori 4 өнгөт машин, 4+4, 4+0 өнгө, B2/A2 формат).
  - `CTP_PLATE_PRICE_SMALL = 6,800₮`: Жижиг CTP хавтан 65*55 (Ryobi 1 өнгөт машин, 1+1, 1+0 өнгө, B3/A3/65*55 формат).
- **Хавтангийн тоо бодох стандарт**:
  - **Хавтас (Cover) болон Нэг хуудаст бүтээгдэхүүн (Bags, Single sheets)**: Хавтас болон торон бүтээгдэхүүн нь татаж хөмрөх (work-and-turn) нэг хэвэнд урд ба арын нүүрийг хувааж хэвлэдэггүй. Иймд урд өнгө ($X$) + арын өнгө ($Y$, +-ийн ард авсан тоо) бүрэн нэмэгдэж $\text{Нийт хавтан} = \text{Setups} \times (X + Y)$ бодогдоно:
    - `1+0` $\rightarrow$ 1 хавтан
    - `1+1` $\rightarrow$ **2 хавтан**
    - `2+0` $\rightarrow$ 2 хавтан
    - `2+1` $\rightarrow$ **3 хавтан**
    - `2+2` $\rightarrow$ **4 хавтан**
    - `3+0` $\rightarrow$ **3 хавтан**
    - `3+1` $\rightarrow$ **4 хавтан**
    - `3+3` $\rightarrow$ **6 хавтан**
    - `4+0` $\rightarrow$ 4 хавтан
    - `4+1` $\rightarrow$ **5 хавтан**
    - `4+2` $\rightarrow$ **6 хавтан**
    - `4+4` $\rightarrow$ **8 хавтан**
    - `5+0` $\rightarrow$ **5 хавтан**
    - `5+1` $\rightarrow$ **6 хавтан**
    - `алтлаг`, `бронз`, `мөнгөлөг` $\rightarrow$ **1 хавтан** (Спот металл 1 өнгө)
  - **Дотор хуудас (Inner pages)**:
    - Бүрэн хуудас: $\text{FullSheets} \times (X + Y)$
    - Бутархай хуудас:
      - Урд ба ар талын өнгө тэнцүү үед ($X = Y$, жишээ нь 1+1, 2+2, 3+3, 4+4) татаж хөмрөх (work-and-turn) зарчмаар 1 хэвэнд хоёр талын нүүр багтах тул $\text{FractionalSetups} \times X$ (жишээ нь 3+3 үед 3 хавтан)
      - Урд ба ар талын өнгө зөрүүтэй үед ($2+1, 3+1, 4+1, 4+2, 5+1$ гэх мэт) татаж хөмрөх боломжгүй тул $\text{FractionalSetups} \times (X + Y)$ буюу +-ийн ард авсан утгаар хавтан бүтэн нэмэгдэнэ.
  - **Өнгөний жагсаалт ба UI стандарт**:
    - Хавтас болон хуудасны өнгөний сонголт нь багаасаа ихрүү (`1+0`, `1+1`, `2+0` ... `5+1`, `алтлаг`, `бронз`, `мөнгөлөг`) дарааллаар эрэмбэлэгдэнэ.
    - Өнгөний ард хаалтад байсан урт тайлбарууд хасагдаж, зөвхөн цэвэр код (`4+0`, `3+1` гэх мэт) харагдана.

### З. Календарийн спираль үдээсний стандарт (Calendar Spiral Binding)
- **Ширээний А5 (26 нүүр / 13 хуудас)**: 1 ширхэгт 24 ш спираль $\rightarrow \text{Qty} = \text{total\_qty} \times 24$
- **Ширээний B5 (26 нүүр / 13 хуудас)**: 1 ширхэгт 28 ш спираль $\rightarrow \text{Qty} = \text{total\_qty} \times 28$

### И. Санхүүгийн үнийн бодолтын дэс дараалал (Pricing Waterfall)
1. **Өртгийн ангилал**:
   - $\text{PreProfitBaseCost (Ашгийн өмнөх суурь өртөг)} = \sum \text{Материал} + \sum \text{Ашгийн өмнөх ажиллагаанууд} + \sum \text{Гадуур ажил} + \text{Хэвлэлтийн өртөг}$
   - $\text{PostProfitTotalCost (Ашгийн дараах шууд өртөг)} = \sum \text{Ашгийн дараах ажиллагаанууд} + \text{Эх бэлтгэлийн зардал}$
   - $\text{FactoryTotalCost (Үйлдвэрийн нийт өртөг)} = \text{PreProfitBaseCost} + \text{PostProfitTotalCost}$
2. **Нэгжийн өртөг**:
   - $\text{Нэгжийн өртөг} = \text{FactoryTotalCost} / \text{Нийт бүтээгдэхүүний тоо}$
3. **Цэвэр үнэ (Ашигтай үнэ)**:
   - $\text{Цэвэр үнэ} = (\text{PreProfitBaseCost} \times \text{Ашиг}) + \text{PostProfitTotalCost}$
   *(Энд Ашиг нь 2.3 гэх мэт үржигдэхүүн бөгөөд ашгийн дараах ажиллагаанууд дээр ашиг үржигдэхгүй шууд нэмэгдэнэ)*
4. **Эцсийн үнэ (НӨАТ-тай)**:
   - $\text{Эцсийн үнэ} = \text{has\_vat} \ ? \ (\text{Цэвэр үнэ} \times 1.10) \ : \ \text{Цэвэр үнэ}$
5. **Нэгжийн үнэ**:
   - $\text{Нэгжийн үнэ} = \text{Эцсийн үнэ} / \text{Нийт бүтээгдэхүүний тоо}$
6. **Ашгийн дараах ажиллагааны стандарт (`is_post_profit: true`)**:
   - Эх бэлтгэл (Design), Лак (Хэсэгчилсэн, Барзгар, Бүтэн), Эмбосс, Клише, Хэв даралт, Хатуу хавтас (A4, A5, B4, B5), Супер хавтас, Гар ажиллагаа, Нууцлал наах гэх мэт тусгай дамжлагууд анхдагчаар ашгийн дараах ангилалд тооцогдоно. Админ болон борлуулагч үнийн сан болон маягт дээр үе шатыг шууд солих (toggle) эрхтэй.

## 🛠️ 4. ХӨГЖҮҮЛЭЛТ БОЛОН GIT СТАНДАРТ (DEVELOPMENT & GIT RULES)

1. **Git Commit салгаж хийх (CRITICAL)**:
   - Хэрэглэгчийн Git түүхийг цэвэр байлгах үүднээс **Backend** болон **Frontend** хавтаст хийгдсэн өөрчлөлтүүдийг **ҮРГЭЛЖ ТУС ТУСАД НЬ САЛГАЖ COMMIT ХИЙНЭ**.

     ```bash
     git add backend/...
     git commit -m "feat(backend): ..."
     git add frontend/...
     git commit -m "feat(frontend): ..."
     ```
2. **TypeScript алдаа шалгах**:
   - Frontend дээр кодын өөрчлөлт хийсний дараа заавал `cd frontend && npx tsc --noEmit` командыг ажиллуулж шинээр алдаа үүсээгүйг шалгаж баталгаажуулна.
